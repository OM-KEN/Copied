# 3.5.6 内联结果布局回归排查

2026-09-29。对比本地正式 tag `v3.5.5`（`d031daf`）与 `v3.5.6`（`cd38c0b`），再用合成输入运行两版生产窗口代码、仅恢复一条监听的控制版本和当前修复代码。环境为 macOS 26.6.2 / Apple Silicon；所有输入使用独立命名剪贴板，日志仅记录合成用例标识、布尔状态和窗口几何。

## 版本变更与根因

3.5.5 到 3.5.6 共三个提交：

- `4fdac23` / #15：精简复制处理、复用字数和词典释义、调整慢目录缓存与窗口生命周期。这是引入本次回归的提交。
- `d564393` / #16：显示多文件复制的总大小。它没有进一步修改本次相关的 ToastView / ToastWindowController / LookupAction / MathExpressionEvaluator。
- `cd38c0b`：版本号变更为 3.5.6。

`4fdac23` 从 ToastView 删除了结果变化后的布局监听：

```swift
.onChange(of: viewModel.resultOverlay) {
    onNeedsLayout?()
}
```

剩下的 `contentTransitionID` 监听覆盖 base、enrichment、loading 等内容更新，但内联结果只写 `resultOverlay`，不会递增该 ID。与此同时，`showResultOverlay` 保留了旧实现：测量新的 `hosting.fittingSize` 后只动画调整外层 NSPanel，没有同步内部 NSHostingView 的 frame。3.5.5 靠被删除的监听异步调用 `updateWindowSize()` 完成内部布局；删除监听后，这条必要的依赖消失了。

因此计算本身成功，显示文本和复制值均正确，失败发生在结果展示阶段。该版本对数学求值器仅删除了未使用的 `DecimalProfile.significantDigits` 字段，没有改变运算逻辑。

当时的数学测试检查求值与格式化，AppBehaviorTests 没有点击计算后真实 NSHostingView / NSPanel 尺寸的断言，因而未捕捉这次界面回归。精简报告记录的词典点击、长文本和内存验收也不能替代内联结果布局验证。

## 受影响范围与版本对照

每份源码运行相同的 12 个场景。尺寸为逻辑 pt，负的内容顶边差值表示下移。所有版本的合成计算与转换复制值均符合对应版本的策略。

翻译走 `showInlineResult()`，它本来就调用 `updateWindowSize()`，所以没有这次回归。3.5.5 的翻译对照直接调用该生产展示入口，其他版本由 LookupAction 展示同一合成释义。缩略图和详情更新仍递增 `contentTransitionID`；Action 到达仍显式请求布局，均未复现尺寸失配。3.5.5 的空转换允许复制空值，3.5.6 将空值规范化为 nil；表中对该场景比较的是布局，不把这项有意行为修正算作回归。

展开态还有一项较早就存在的问题：旧 `showResultOverlay` 用未包含展开态阴影预留的 fittingSize 设置外窗。三行转换需要外窗 428×183、hosting 396×167 且原点为 (16,16)，旧动画最终却把外窗设为 396×167。这在 3.5.5 和仅恢复监听的 3.5.6 中都出现。当前修复直接调用包含阴影预留的统一布局函数，也覆盖了这一问题。

## 修复与回归覆盖

生产修复保持为 `ToastWindowController.showResultOverlay()` 调用现有 `updateWindowSize()`，同步内部视图与外窗，并保留展开态的阴影预留。

`Tests/AppBehaviorTests.swift` 的 `inlineResultsFitProductionWindow()` 覆盖精确/近似/错误计算、拼音、多行和空插件转换、翻译以及展开态插件菜单操作，验证复制值、真实 hosting 尺寸、外窗尺寸、内容顶边与原生展开正文。当前修复代码的 12 个对照场景全部符合这些布局检查。

验证：扩展后的生产窗口回归与 `./run-tests.sh` 全量通过，`git diff --check` 通过，生产构建指纹与当前源码一致。

排查范围为 3.5.6 改动涉及的内联结果、窗口布局和异步内容更新路径。临时源码副本、探针和文件日志在验收后删除。
